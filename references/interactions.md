# 交互与门禁

## 1. 什么时候才做门禁

只有当学习者必须做出一个可观测判断，并且这个判断改变后续理解，才做门禁。

推荐每课 1–2 道，长课最多 3 道。不要每节都放一道题来制造“互动感”。

侧栏参考资料与纯手感实验不产证据。

## 2. 题型选择

| 认知判断 | 类型 | 典型实现 |
|---|---|---|
| 定义、辨析、真假、结果预测 | `choice` | 单选 |
| 图上哪个位置 / 哪个节点 | `hotspot` | 图上点选 |
| 哪些属于 A / B | `bucket` | 归类 |
| 步骤 / 顺序 | `sequence` | 排序 |

不要为了统一而全部做单选。

## 3. 门禁锚点

### 场景开始

适合考**前面已经讲过**的内容。门禁在本场景开始前出现。

### `at: 'end'`

适合考本场最后一句刚讲完的内容。锚点必须是：

```js
lastNarration.start + lastNarration.duration
```

而不是“最后一句的 `index`”。否则会在最后一句开头就停，直接掐断旁白。

### 不要在句中打开

门禁应该落在场景开始或某句结束后的空档。

## 4. 页面门禁控制器

```js
var GATES = [
  {scene:'seg-2', type:'sequence', preGate:true, ...},
  {scene:'seg-3', type:'choice',   preGate:true, ...},
  {scene:'seg-4', at:'end', type:'hotspot', preGate:true, ...}
];
```

`preGate` 只负责短暂过渡，不承担新的学习内容。

同一个 scene 最多挂一个 gate；runtime 的 gate-host 是单槽位，重复配置会被 QA 判错。

门禁浮在画布内。播放器行保留在下面，但变灰且不可点，避免绕过门禁。

答对后给明确的“继续”按钮，不自动跳走。

## 5. 错答 / 对答状态

页面观察：

```js
MutationObserver → data-locked
```

错误：

```text
反馈出现 → 不锁 → 继续隐藏
```

正确：

```text
data-locked="1" → 禁用当前题目 → 显示继续
```

## 6. 提示文案

反馈只回答：为什么错、为什么这次对。

不要把完整讲稿再塞进题目卡里；门禁是一个判断点，不是第二条字幕轨。

## 7. 自检

- [ ] 题型与认知动作匹配；
- [ ] 题面只考已经讲过的内容；
- [ ] 锚点在句首或句尾，不截断旁白；
- [ ] 错答不写 `data-locked`；
- [ ] 对答写 `data-locked="1"`；
- [ ] 对答后继续按钮明确可见；
- [ ] 没有把门禁题面重复写成字幕；
- [ ] `choice` / `hotspot` 恰好一个正确项；
- [ ] `sequence` 的 `correct_order` 与全部条目一一对应；
- [ ] `bucket.answer` 完整覆盖全部条目，且只引用已存在的筐。
